创建连接

为了方便传输，会需要某些连接的协议。就如大部份的游戏，游戏制作者提出四不同类型的 连接：IPX，TCP/IP，Modem，和序列。这IPX 连接(更精确地说，他是一个协议)，几乎在完 全透明的情形下操作，它能被使用于和相同局域网络中的其它人玩游戏，它必须要被安装在 你的计算机上来使用(假如它无效，查阅这窗口说明文件，或到这窗口控制台，网络项目中， 并增加这IPX protocol)；TCP/IP 是这因特网协议，它可以用于与这因特网上任何其它的玩 家玩游戏，假设你知道他们的IP 地址，在一区域性的网络，你不须提供地址就能使用它； 一调制解调器连接是透过调制解调器，你必须提供某些调制解调器设定(一个最初设定的字 符串和一个电话号码)以使用它；最后，当使用一序列串接线(在计算机之间直接的连接)你 需要到提供一些埠的设定。有四个GML函式能用于初始化这些连接:

mplay_init_ipx() 初始化 IPX 连接.
mplay_init_tcpip(addr) 初始化TCP/IP 连接. addr 是一个包含这网页地址或IP 地址的字符串，例如：'www.gameplay.com'或 '123.123.123.12'，也许后面还有一埠号(例如'：12')，只有当参加一联机时(看下面)你需 要提供一个地址，在一区域性网络地址是不需要的。
mplay_init_modem(initstr,phonenr) 初始化一调制解调器连接，initstr 是这调制解调器 初始设定的字符串 (可以是空的)；phonenr 是一包含使这电话号码响的字符串(例如 '0201234567')，只有当参加一联机时(看下面)你必须要提供一电话号码。
mplay_init_serial(portno,baudrate,stopbits,parity,flow) 初始化一序列连结， portno 是埠号(1-4)，baudrate 是使用的鲍率(100-256K)，stopbits 指出这停止的笔数 (0=1笔，1=1.5笔，2=2笔)。parity指出这同等(0=none，1=奇数，2=偶数，3=标示)，flow 指出流程控制的类型(0=none，1=xon/xoff，2=rts，3=dtr，4=rts和dtr)，返回是否成功， 一个代表性的呼叫是mplay_init_serial(1，57600，0，0，4)。把0当作第一个参数以打开 一对话框，使得使用者可以改变设定，这些函式其中的一个将会被你的游戏呼叫，恰好一次。 全部的函式会回报他们是否成功。假如这特殊的协议在你的机器上没有安装，或是不支持， 则他们是不会成功的，你能使用这下面函式来检查是否有一有效成功的连结：

Your game should call one of these functions exactly once. All functions report whether they were successful. They are not successful if the particular protocol is not installed or supported by your machine. To check whether there is a successful connection available you can use the following function

mplay_connect_status() 返回目前连结的状况。 0=不连结，1=IPX 连结，2=TCP/IP 连结，3=modem 连结，和4=序列连结。

mplay_end() 结束目前连结。

mplay_ipaddress() 返回你计算机的IP 地址(例如'123.123.123.12')当作一字符串， 你能例如在屏幕上某处显示这地址，注意这例行程序是缓慢的，所以不要常常呼叫它。
